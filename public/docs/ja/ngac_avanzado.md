# 上級レベル

> [!重要]
> 高度なレベルでは、「ポリシー」またはポリシー クラスとして知られる複数のグラフの結合を開始し、時間や場所 (NGAC 内の ABAC) などの動的属性を追加します。

## 条件付き評価

高度な NGAC では、グラフ内の 1 つのパスでは十分ではありません。 「条件」を関連付けることができます。

### 時間とステータスの制限

「人魚」
グラフTD
    U[ユーザー: レジ係] -->|UA|レジ係（レジ係）
    
    レジ係 -- 処理可能 --> OA1 (レジ)
    
    レジ係 - 。条件: 勤務時間のみ -> OA1
    
    O[ボックス 01] --> OA1
    O2[ボックス 02] --> OA1
「」

ユーザー「Cashier」が午前 3 時に「Cash 01」にアクセスしようとすると、NGAC エンジンはその方法を見つけますが、エッジ条件は失敗します。したがって、アクセスは拒否されます。

### 職務の分離 (SoD)

NGAC を使用すると、**禁止制約**を宣言することで SoD を簡単に実装できます。 
- アリスが購入リクエストを承認すると、グラフはアリスが同じ購入の小切手に署名する権利を**拒否**するノードを動的に生成します。

> [!ヒント]
> 動的なオブジェクト属性を利用することで、何百万ものロールを作成することなく、きめ細かい方法で情報を分離できます (ロールの爆発)。
