# AWS エキスパート：イベント駆動型アーキテクチャ、SQS、SNS、および EventBridge

これまで、私たちは同期的な Lambda を使用してきました：ユーザーが HTTP Request を行い、500ms 待ち、HTTP Response を受け取ります。

しかし、ユーザーアカウントを作成する際に、PDFを生成し、3通のウェルカムメールを送信し、支払いを処理し、会社に通知する必要がある場合はどうなるでしょうか？ HTTPを処理するLambdaでこれらすべてを行うと、ユーザーは12秒間ロード画面を見つめることになります。さらに悪いことに、11秒目にメールサービスが失敗した場合、トランザクション全体を失います。

エンタープライズアーキテクチャでは、**非同期およびイベント駆動型 (Event-Driven)** モデルに移行します。

## 1. AWS メッセージングの三頭政治

```mermaid
graph TD
    API[API Gateway] --> LambdaAuth[Lambda ユーザー作成]
    LambdaAuth -->|UsuarioCreado イベントを公開する| Broker{イベントバス}
    LambdaAuth -.->|即座に 201 で応答する| Usuario
    
    Broker -->|"通知する (Fan-Out)"| Queue1[SQS キュー (メール)]
    Broker -->|"通知する (Fan-Out)"| Queue2[SQS キュー (支払い)]
    Broker -->|"通知する (Fan-Out)"| Queue3[SQS キュー (レポート)]
    
    Queue1 --> LambdaEmail[Lambda メール送信]
    Queue2 --> LambdaPago[Lambda 支払い処理]
```

### AWS SNS (Simple Notification Service)
**Pub/Sub (パブリッシャー/サブスクライバー)** システムです。Lambda は「単一の」メッセージを SNS の "トピック (Topic)" に送信します。そのトピックは、クローンされたメッセージを何千ものサブスクライバーに即座に配布します（Fan-Out 効果）。

### AWS SQS (Simple Queue Service)
**メッセージキュー (Queue)** です。メッセージは蓄積され、処理されるのを待ちます。これは「圧力（Backpressure）」を制御するために基本となるものです。
ブラックフライデーに50,000件の購入を受け取った場合、一度に50,000個の支払いLambdaを呼び出して銀行のゲートウェイをクラッシュさせる代わりに、SQSがそれらを保持し、Lambdaが1分間に100個ずつ処理していくことで、0%の失敗を保証します。

### Amazon EventBridge (企業バス)
巨大なマイクロサービスアーキテクチャ向けのSNSの進化版です。インテリジェントなフィルタリングルールを作成できます。
例：EventBridge は JSON を受け取ります。JSON に `"tipo": "PAGO_RECHAZADO" (支払い拒否)` と書かれている場合、他のマイクロサービスを起こすことなく、不正（Fraude）マイクロサービスに直接ルーティングします。

## 2. Dead Letter Queues (DLQ)

マーフィーの法則により、システムは必ず失敗するとされています。SendGridがダウンしているためにメールを送信するLambdaが失敗した場合はどうなるでしょうか？

SQS のおかげで、Lambda が例外をスローした場合、メッセージはキューに戻され、自動的に再試行されます。3回連続して失敗した場合、メッセージは **デッドレターキュー (Dead Letter Queue / DLQ)** に送信されます。
これにより、あなたは寝に行くことができます。翌日、DLQを確認し、コードのバグを修正し、AWSに「この500件の失敗したメッセージを再処理して」と伝えます。データが失われることは決してありません。

## 3. 最大の回復力 (レジリエンス)
このパターンを使用すると、API は常に 50 ミリ秒で応答します。重い作業は、自動スケーリング、自動再試行、データ損失なしに、分散された方法でバックグラウンドで実行されます。これがクラウドの真の力です。

**最適化**レベルでは、C/RustのLambda、Provisioned Concurrency、およびマイクロ秒のキャッシュのためのDAXを通じて、財務コスト（FinOps）とボトルネックを絞り出します。
