# Docker 初期：コンテナの構成とアーキテクチャ

コンテナ革命へようこそ。Dockerは単なる仮想化ツールではなく、ソフトウェアをパッケージ化し、配布し、実行する方法におけるパラダイムシフトです。「私のマシンでは動く」という時代は終わりました。

## 1. 仮想化 vs コンテナ化

Dockerを理解するには、まず従来の仮想マシン (VM) と比較して、Dockerがどのような問題を解決するのかを理解する必要があります。

### 比較アーキテクチャ図

```mermaid
graph TD
    subgraph sub_1 [従来の仮想マシン]
        HW1[物理サーバー / ハードウェア] --> Hyper[ハイパーバイザー (VMware / Hyper-V)]
        Hyper --> VM1[VM 1: 完全なゲストOS + App A]
        Hyper --> VM2[VM 2: 完全なゲストOS + App B]
    end

    subgraph sub_2 [Docker コンテナ]
        HW2[物理サーバー / ハードウェア] --> SO[ホストOS]
        SO --> Engine[Docker Engine]
        Engine --> C1[コンテナ: バイナリ/ライブラリ + App A]
        Engine --> C2[コンテナ: バイナリ/ライブラリ + App B]
    end
```

**根本的な違い:** 仮想マシンは*ハードウェア*全体を仮想化し、完全なオペレーティングシステム (OS) をインストールします（これには数ギガバイトの容量と、起動に数分かかります）。Dockerは、Linuxカーネルのネームスペース (namespaces) とcgroupsを使用して*オペレーティングシステム*を仮想化します。コンテナは同じカーネルを共有するため、容量は数メガバイトになり、数ミリ秒で起動します。

## 2. ゼロ・フリクション (摩擦なし) でのインストール

オペレーティングシステムによってインストール方法は異なりますが、開発における業界標準は、（Windows/Mac用の）**Docker Desktop**と、Linux用の生の**Docker Engine**です。

### 環境の確認
ターミナルを開き、以下を実行します：

```bash
docker version
```
クライアント (Client) の情報は表示されるが、サーバー (Server または Daemon) についてのエラーが表示される場合は、Dockerエンジンがバックグラウンドで実行されていないことを意味します。続行する前にDockerサービスを開始してください。

## 3. 最初のコンテナ：クラシックな NGINX

まだコードは書きません。ライフサイクルを理解するために、既存のイメージを消費 (利用) してみましょう。

```bash
# コンテナのポート80をホストのポート8080にマッピングして、バックグラウンドでWebサーバーを実行します
docker run -d --name mi-servidor-web -p 8080:80 nginx:alpine
```

### コマンドの構造（アナトミー）:
* `run`: エンジンにローカルでイメージを探すよう指示します。存在しない場合は、Docker Hubからダウンロードし、コンテナを作成して起動します。
* `-d` (Detached / デタッチ): コンテナをバックグラウンドで実行し、ターミナルを解放します。
* `--name`: 読みやすい名前を割り当てます。これを省略すると、Dockerは `jolly_turing` のようなランダムな名前を割り当てます。
* `-p 8080:80`: ポートマッピング（ポート転送）。あなたの `localhost:8080` に到達したトラフィックは、コンテナ内のポート `80` にリダイレクトされます。
* `nginx:alpine`: 使用するイメージ。`alpine` は超軽量の Linux バリアント (約 5MB) であり、すべてのクラウドアーキテクトがセキュリティと速度のために好むべきものです。

ブラウザで `http://localhost:8080` にアクセスしてください。NGINXのウェルカムページが表示されたら、最初のコンテナのデプロイは成功です。
