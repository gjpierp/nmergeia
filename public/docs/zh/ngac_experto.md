# NGAC 指南：专家级

> [!警告]
> 企业级 NGAC 需要严格控制策略决策点 (PDP) 性能（延迟）和可用性。

## NGAC分布式架构

在云原生系统中，不能让 PDP 成为瓶颈或单点故障 (SPOF)。 

### 图分片和缓存

````美人鱼
图解TD
    API[API 网关] --> PEP[策略执行点]
    
    PEP --> CACHE[(Redis / Memcached)]
    
    CACHE --“缓存未命中”--> PDP[NGAC 策略决策点]
    
    PDP --> GDB[(图形数据库 - Neo4j / ArangoDB)]
    
    PIP[策略信息点] -->|更新上下文|等离子显示面板
````

为确保延迟小于 10ms：
1. **PEP 级缓存：** 如果策略不是很不稳定，则记住授权结果几分钟（记忆化）。
2. **图数据库：** 使用原生图数据库（例如 Neo4j、Amazon Neptune）以避免 SQL 所需的昂贵的递归“JOIN”。

## 持续审计和合规性

NGAC 在监管分析（合规性）方面表现出色。您可以运行“审查”算法来检测策略设置中的漏洞。

> [!注意]
> 通过 Neo4j 中的 Cypher 查询，您可以从数学上证明 **“没有外部用户具有连接到标有 PII 的对象的路径”**，为审计人员提供正式保证。
